# S16: бот и размещение пилота

## Ссылки и доступность чата

Ссылка на игру: `https://t.me/<bot_username>?start=g_<game_uuid>`. Она вызывает `/start` в приватном чате;
ответ содержит кнопку `web_app` на конкретную игру. После Telegram-входа TMA открывает маршрут из кнопки.
Также поддерживается прямой запуск `?startapp=g_<game_uuid>`: TMA проверяет формат параметра и восстанавливает
маршрут после входа. Для неизвестного UUID API показывает «Игра не найдена». Запуск `/start` без аргумента
открывает список.
Неверный параметр и отсутствующая игра ведут к списку, без отражения пользовательского текста в сообщении.

`POST /telegram/webhook` принимает только запросы с `X-Telegram-Bot-Api-Secret-Token`. Для приватного `/start`
сохраняется соответствие Telegram user ID и private chat ID; `can_message=true` означает полученный `/start`,
но не гарантию будущей доставки. Ответ Telegram `403` помечает чат недоступным. При отправке в S17–S18 нужно
повторно учитывать `can_message` и отмечать блокировку по ответу Telegram. Открытие `startapp` без `/start`
само по себе не подтверждает право отправки сообщений.

Перед регистрацией webhook владелец должен задать bot username, HTTPS URL Mini App и секретный заголовок;
`setWebhook` ограничить `allowed_updates=["message"]`. В BotFather настроить Main Mini App URL, иначе
прямая ссылка `startapp` не откроет приложение. Для кнопки `web_app` нужен HTTPS URL. Токен и секрет не
передавать в переписке и не сохранять в Git.

## Конкретная схема пилота

Предлагаемый вариант: VM Yandex Compute Cloud в `ru-central1`, управляемый PostgreSQL в той же зоне,
API NestJS и отдельный процесс worker на VM, HTTPS через Nginx с сертификатом ACME. Статический TMA остаётся
на GitHub Pages. БД принимает соединения только из сети VM; на VM открыты 80/443 и ограниченный SSH.
Для разработческой проверки с настоящими Telegram-аккаунтами использовать отдельный HTTPS-стенд в РФ;
локальный `start:https` на mkcert доступен только локально и публичным туннелем не является.

До оплаты проверить на официальных страницах Yandex Cloud актуальные тарифы Compute Cloud, Managed PostgreSQL,
диска, трафика и резервных копий в `ru-central1`, а также договор, условия обработки персональных данных,
расположение резервных копий и юридическую пригодность схемы. Из этой среды страницы провайдера и Telegram
не удалось открыть из-за сетевого/сертификатного сбоя; конкретная цена и соответствие законодательству **не
подтверждены**. Расход за месяц рассчитать в калькуляторе по выбранным размерам до создания ресурсов.
Статический GitHub Pages загружает код и публичные ресурсы TMA; пользовательские данные хранит API/БД.

Конфигурация API: `NODE_ENV=production`, `HOST=127.0.0.1` за reverse proxy, `PORT`, `DATABASE_URL`,
`FRONTEND_ORIGINS`, `LOG_LEVEL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_APP_URL`.
Конфигурация сборки TMA: `VITE_API_URL` (публичный HTTPS API), `VITE_TELEGRAM_BOT_USERNAME` (без `@`).
Значения секретов хранятся в секретном хранилище облака или на VM с ограниченными правами; frontend получает
только публичные адрес и username. При размещении worker в S17–S18 ему понадобятся те же БД и токен бота;
конкретная команда запуска и переменные появятся вместе с worker.

Порядок выпуска: подготовить изолированную БД; проверить backup и восстановление в отдельную БД; выполнить
`prisma migrate deploy` из версии релиза; запустить API и дождаться readiness; настроить HTTPS и webhook;
запустить worker после реализации S17–S18; собрать TMA с публичными переменными и проверить две тестовые
учётные записи. Для отката остановить worker, снять webhook или направить его на прежнюю здоровую версию,
вернуть прежний API и TMA. Миграцию с удалением/изменением данных назад автоматически не откатывать:
при несовместимой схеме восстановить снимок в отдельную БД, проверить данные и переключить подключение.
На текущем шаге внешний ресурс не создавался, webhook не регистрировался и пилот не публиковался.

Действия владельца: подтвердить провайдера и юридическую проверку, создать аккаунт/платёжный профиль и
DNS, обеспечить секреты в хранилище, настроить бота в BotFather, предоставить доступ к тестовым аккаунтам
для согласованной проверки перехода. Ни один токен не требуется отправлять в чат.

# Контракт REST игр (S03)

Редактируемый источник REST — [`contracts/main.tsp`](../../contracts/main.tsp). TypeSpec генерирует OpenAPI 3;
из него `openapi-typescript` создаёт типы путей и схем, используемые `openapi-fetch` в `@picklehub/api`.
OpenAPI и клиент — производные файлы: менять их вручную запрещено. Версии компилятора, emitter и генератора
зафиксированы корневым `package-lock.json`. `npm run contracts:check` повторно генерирует артефакты и выявляет
отличие от сохранённых версий.

## Модель и правила

- В контракте сущность называется `Game`; в интерфейсе TMA она может показываться как «Игра». Организатор
  (`organizerId`) и запись (`Participant`) независимы. `organizerParticipates` по умолчанию `true`; организатор
  может управлять игрой без участия. Если участвует, он занимает одно место и присутствует среди участников.
- `participantCount` соответствует числу действующих участников и включает организатора-участника.
  Ограничение `participantLimit` — от 2 до 32 включительно; нельзя уменьшить его ниже текущего состава.
  Запись в полную игру возвращает 409 `GAME_FULL`. Проверка доступного места и создание участия атомарны:
  при гонке за последнее место только один запрос получает участие, проигравший — `GAME_FULL`.
- Статус `SCHEDULED` автоматически становится `FULL` при заполнении и возвращается в `SCHEDULED` при
  освобождении места. `CANCELLED` терминален. Отмена, начало игры и права доступа закрывают соответствующие
  команды; запись и выход доступны до начала. Сервер отклоняет даты не в будущем.
- Все поля времени — RFC 3339 date-time с UTC `Z`. `durationMinutes`: целое от 30 до 480. Название площадки
  1–120 символов, адрес 1–300, описание до 2000, подсказка уровня 1–80. Уровень — свободная подсказка,
  не проверка допуска. Строки обрезаются по краям и после этого проходят указанные ограничения.
- Список содержит только будущие игры не в статусе `CANCELLED`, сортируется по `startsAt`, затем по `id`.
  `limit` по умолчанию 20, диапазон 1–50; `cursor` непрозрачный, привязан к сортировке. `nextCursor`
  отсутствует на последней странице. Детали возвращают состав, включая безопасные `userId` и `displayName`.

## Маршруты и повторы команд

Все маршруты игр требуют Bearer-токен сессии. `/sessions/telegram` принимает `initData`; он проверяется backend
по Telegram правилам и никогда не отражается в ошибке или логах. Пустой токен не является авторизацией.

| Метод и путь                                   | Назначение                                                         | Идемпотентность                |
| ---------------------------------------------- | ------------------------------------------------------------------ | ------------------------------ |
| `GET /games?cursor&limit`                      | Список и пагинация                                                 | Не требуется                   |
| `GET /games/{gameId}`                          | Игра и состав                                                      | Не требуется                   |
| `POST /games`                                  | Создание, с исходным участием согласно `organizerParticipates`     | Обязательный `Idempotency-Key` |
| `PATCH /games/{gameId}`                        | Частичное изменение; `null` очищает уровень/описание               | Обязательный `Idempotency-Key` |
| `PUT /games/{gameId}/participation`            | Запись текущего игрока; для организатора — включение участия       | Обязательный `Idempotency-Key` |
| `DELETE /games/{gameId}/participation`         | Выход; для организатора — выключение участия без потери управления | Обязательный `Idempotency-Key` |
| `DELETE /games/{gameId}/participants/{userId}` | Удаление участника организатором                                   | Обязательный `Idempotency-Key` |
| `POST /games/{gameId}/cancellation`            | Отмена организатором                                               | Обязательный `Idempotency-Key` |
| `POST /sessions/telegram`                      | Проверка initData и выдача Bearer-сессии                           | Не применяется                 |

Ключ — 16–128 символов. Сервер хранит ключ в области аккаунта, вместе с хешем метода, пути и тела,
не менее 24 часов. Повтор с тем же ключом и запросом возвращает исходный HTTP-статус и тело; тот же ключ
с другим запросом — 409 `IDEMPOTENCY_KEY_REUSED`. Валидационные ошибки не фиксируют результат ключа.
Команды записи, выхода и организатора являются идемпотентными также по целевому состоянию: повторная запись
не создаёт второе участие, повторный выход не меняет состав второй раз.

## Ошибки

Ошибки имеют `{ code, message, requestId, details? }`. `details` содержит машинно-читаемые поля ошибок без
секретов и initData. Используются HTTP 400 `VALIDATION_ERROR`, 401 `UNAUTHENTICATED`, 403 `FORBIDDEN`,
404 `GAME_NOT_FOUND`/`PARTICIPANT_NOT_FOUND`, 409 `GAME_FULL`/`GAME_CONFLICT`/
`IDEMPOTENCY_KEY_REUSED` и 410 `GAME_CANCELLED`. Для конфликтов используется общая схема `ConflictError`;
`code` различает `GAME_FULL`, `GAME_CONFLICT` и `IDEMPOTENCY_KEY_REUSED`. Неавторизованный доступ, чужая
игра, отмена и невалидное время не должны приводить к частичному
изменению данных. Ошибка конкурентной записи не требует повторной загрузки формы: клиент обновляет игру и
показывает актуальный состав.

## Проверка воспроизводимости

После изменения `.tsp` выполнить `npm run contracts:generate`. Сгенерированные `contracts/openapi/` и
`frontend/packages/api/src/generated/` хранятся в git для review и работы без запуска генератора. Затем выполнить
`npm run contracts:check`: повторная генерация должна дать те же байты и git diff не должен содержать
изменения сгенерированных файлов. Исправления схемы вносятся только в TypeSpec.

# Минимальная архитектура Telegram MVP

## Границы приложений и пакетов

- `frontend/tg/` — React Mini App: экраны, навигация, состояние интерфейса и адаптация к Telegram SDK.
- `frontend/packages/api/` — будущий TypeScript-клиент, генерируемый из OpenAPI. Источник REST-контракта — `contracts/` на
  TypeSpec. Компоненты используют API-слой, а не собственные `fetch`-вызовы и не типы Prisma.
- `frontend/packages/tokens/` — будущие платформонезависимые значения цветов, типографики, размеров и скруглений.
  Tailwind/CSS потребляет их для web; React Native сможет использовать те же значения без браузерных компонентов.
- `backend/` — будущий NestJS-модульный монолит, бизнес-правила, проверка Telegram init data, доступ к PostgreSQL через
  Prisma и отправка уведомлений. Frontend не импортирует код backend.
- `contracts/` — редактируемые TypeSpec-источники REST. AsyncAPI добавляется при появлении событийного интерфейса.

## Правила зависимостей

1. TMA зависит от API-клиента и токенов; API-клиент зависит от сгенерированных контрактных типов.
2. Общие пакеты не импортируют приложение TMA. UI-компоненты платформы между TMA, web и mobile не переносятся автоматически.
3. Серверные модели и инфраструктура остаются внутри backend; публичные DTO задаются контрактом.
4. Моки подключаются на HTTP-границе клиента и не становятся альтернативным хранилищем или источником типов.
5. Состояние сервера принадлежит TanStack Query. Локальный UI-state остаётся рядом с компонентом; общий store вводится
   только при конкретной межэкранной потребности.

## Контракты и генерируемый код

- TypeSpec — единственный редактируемый источник REST; OpenAPI и клиент воспроизводимо генерируются командами workspace.
- Сгенерированные файлы помечаются заголовком и не редактируются вручную. Исправление модели делается в TypeSpec и затем
  повторной генерацией.
- Генератор и его версия фиксируются в workspace/lock-файле. Проверка CI повторно генерирует артефакты и проверяет diff.
- AsyncAPI становится источником realtime-событий только при согласованном использовании; отдельный realtime transport
  для первого MVP не нужен.

Эта задача создаёт только основу TMA и не добавляет API-контракт, backend или другие клиентские приложения.

Mock Telegram environment, SDK debug mode и Eruda включаются только при `import.meta.env.DEV`. В production нет
отладочных маршрутов или фиктивной авторизации.

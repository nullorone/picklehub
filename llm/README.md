# Промпты реализации PickleHub

По запросу владельца от 2026-10-02 отдельно выполняется [DS01 — основа дизайн-системы](tasks/ds01-design-system-foundation.md). Исправление Button по EIN: [DS02](tasks/ds02-ein-button.md). Решение описано в [ADR-002](_docs/adr-002-design-system.md); S19 остаётся в работе.

Комплект предназначен для последовательной реализации реального MVP стартапа одним разработчиком с AI-агентом.

## Обязательный порядок работы

1. Всегда начинайте с [`00-project-overview.md`](00-project-overview.md).
2. Активный маршрут — [задачи Telegram MVP](tasks/README.md), шаги `S01`–`S20` по порядку.
   Каждая задача находится в отдельном Markdown-файле в `tasks/`;
   [требования MVP](_docs/telegram-mvp-plan.md) задают общий контекст.
   Изменение последовательности зафиксировано в [ADR](_docs/adr-001-telegram-first-mvp.md).
3. Выполняйте один шаг за сессию продолжительностью 30–60 минут. До продуктового кода завершите каркас `S01`.
4. Перед шагом прочитайте его требования, актуальные документы в `_docs/`, контракты и результаты предыдущих шагов.
5. Не переходите дальше, пока критерии приёмки текущего шага не выполнены. Если время истекло,
   запишите остаток и блокировки в `_docs/ai-development-log.md`; продолжите этот же шаг следующей сессией.
6. Изменение продукта сначала отражается в обзоре, требованиях и ADR, затем в OpenAPI/AsyncAPI и только после
   этого в коде.
7. Нельзя выдумывать успешные проверки, лицензии, интеграции, эксплуатационные развёртывания или юридическое
   соответствие.

## Активные релизы

1. Telegram bot + Mini App: создание игровой встречи, состав, запись, управление и уведомления.
2. Web MVP с адаптациями и PWA на общем контракте.
3. React Native для Android/Google Play и iOS/App Store после стабилизации API.

Следующий шаг: `S01` — основа frontend и правила зависимостей. Документирование интервью не означает,
что старый архитектурный промпт или какой-либо шаг реализации уже завершён.

- `00-overview.md`: стабильный контекст, объём работ, зависимости и исключения.
- `01-requirements.md`: продуктовые правила, аналитика и критерии приёмки.
- `02-contract-data.md`: OpenAPI/AsyncAPI, данные, ограничения и события.

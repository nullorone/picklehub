# Промпты реализации PickleHub

Комплект предназначен для последовательной реализации реального MVP стартапа одним разработчиком с AI-агентом.

## Обязательный порядок работы

1. Всегда начинайте с [`00-project-overview.md`](00-project-overview.md).
2. До первого product-кода выполните `01-platform-foundation` целиком.
3. Затем выполняйте каталоги по номеру; внутри каталога — файлы по номеру.
4. Перед каждым промптом прочитайте его `00-overview.md`, актуальные документы в `_docs/`, контракты и результаты предыдущих этапов.
5. Не переходите дальше, пока критерии приёмки текущего промпта не выполнены либо блокировка не записана в `_docs/ai-development-log.md`.
6. Изменение продукта сначала отражается в обзоре, требованиях и ADR, затем в OpenAPI/AsyncAPI и только после
   этого в коде.
7. Нельзя выдумывать успешные проверки, лицензии, интеграции, эксплуатационные развёртывания или юридическое
   соответствие.

## Релизные волны

- Основа платформы: `01`.
- MVP матчей для TMA и web/PWA: `02`–`08`.
- Клубы и соревнования: `09`–`10`.
- Удержание и рекламный инвентарь: `11`–`13`.
- Дополнительные клиенты: `14`–`15`.
- Готовность к эксплуатации: `16`.

## Стандарт каталога фичи

- `00-overview.md`: стабильный контекст, объём работ, зависимости и исключения.
- `01-requirements.md`: продуктовые правила, аналитика и критерии приёмки.
- `02-contract-data.md`: OpenAPI/AsyncAPI, данные, ограничения и события.
- `03-backend.md`: сценарии использования, безопасность, конкурентное выполнение и фоновые задачи.
- `04-tma-web.md`: TMA и web/PWA; для mobile/operations каталога — соответствующий клиентский этап.
- `05-verification.md`: полный набор обязательных проверок и подтверждений.

Шаблоны находятся в [`_templates/`](_templates/). Общие результаты и ADR складываются только в [`_docs/`](_docs/).

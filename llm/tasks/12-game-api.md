# S12. API создания и чтения игр

Статус: не начата. День 2. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [11-telegram-auth.md](11-telegram-auth.md).

## Цель

Сохранять встречи в PostgreSQL и возвращать их через согласованный контракт.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Контракт S03, схема S10 и авторизация S11.

## Выполнить

1. Реализовать создание, список будущих встреч и чтение по идентификатору.
2. Применять серверную валидацию всех полей, будущего времени, лимита и длительности по контракту.
3. Получать организатора из сессии; при включённом участии создавать его место в той же транзакции.
4. Сохранять UTC, отделять организатора от состава; возвращать стабильные статусы и счётчики.
5. Реализовать согласованную идемпотентность создания и ошибки неизвестной встречи.

## Критерии готовности

- [ ] Созданная встреча доступна после перезапуска API.
- [ ] Оба режима участия организатора работают; список и детали соответствуют OpenAPI.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, интеграционные тесты создания/чтения/повтора, контрактные проверки и сборка.
- Проверить невалидные поля, прошлое время и сохранность после перезапуска.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не реализовывать очередь, карту, каталог площадок или рекомендации.

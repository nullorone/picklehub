# S02. Tailwind и минимальные дизайн-токены

Статус: не начата. День 1. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [01-frontend-foundation.md](01-frontend-foundation.md).

## Цель

Оформить каркас в стиле текущего PickleHub через Tailwind и общий источник токенов.

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),

[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Результат S01; текущие цвета, типографика, карточки и навигация прототипа.
- [Визуальная основа](../_docs/legacy-prototype.md).

## Выполнить

1. Выделить в `frontend/packages/tokens/` минимальные цвета, отступы, размеры текста и скругления. Источник значений должен допускать последующее использование в React Native.
2. Настроить смысловые роли цветов и их использование темой Tailwind: фон, поверхность, основной/вторичный текст, акцент, ошибка, граница.
3. Подключить светлую и тёмную темы с учётом Telegram theme parameters и безопасными значениями для локального просмотра.
4. Оформить оболочку, кнопку, поле и карточку. Сохранить текущий визуальный характер; не проектировать полную дизайн-систему.
5. Соблюдать структуру папок компонентов: основной TSX, локальные helpers/hooks/api/tests/types/const/mock по необходимости; CSS Module только для нужных CSS-правил.

## Критерии готовности

- [ ] Базовые элементы используют Tailwind и согласованные токены.
- [ ] Обе темы читаемы, виден клавиатурный фокус; элементы пригодны для узкого экрана.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы и сборка затронутого frontend.
- Визуально проверить обе темы, фокус, длинный текст и узкую ширину; зафиксировать материалы проверки.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не подключать FCC/UI как зависимость, не строить каталог всей дизайн-системы, не создавать native-компоненты.

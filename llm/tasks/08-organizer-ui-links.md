# S08. Управление игрой и ссылка приглашения

Статус: не начата. День 1. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [07-join-leave-roster.md](07-join-leave-roster.md).

## Цель

Дать организатору интерфейс редактирования, управления составом и отмены.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Форма S06, состав S07 и контракт S03.

## Выполнить

1. Переиспользовать форму для редактирования; нельзя уменьшить лимит ниже текущего состава.
2. Добавить удаление участника и отмену с подтверждением конкретного действия.
3. Поддержать изменение собственного участия организатора с сохранением прав управления.
4. Добавить копирование/передачу ссылки на игру; оформить адаптер Telegram deep link для подключения в S16.
5. Показывать действия только организатору, обрабатывать серверный отказ в доступе; видимость кнопок не заменяет backend-проверку.

## Критерии готовности

- [ ] Организатор без участия может редактировать, удалить участника и отменить игру.
- [ ] После мутации все экраны обновляются; у обычного участника нет элементов управления чужой игрой.
- [ ] Прямая ссылка открывает нужный экран в локальном сценарии.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, UI-тесты прав/подтверждений, контрактные проверки и сборка.
- Проверить отказ API, лимит ниже состава и повторную отмену.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не отправлять сообщения реальным игрокам и не считать deep link проверенным в Telegram до S16.

## Завершение сессии

Обнови [журнал](../_docs/ai-development-log.md): изменения, принятые решения, команды,
результаты, фактическое время, блокировки и оставшаяся работа. Если час закончился до приёмки,
запиши остаток и продолжай эту же задачу следующей сессией. Обнови статус этого файла и индекс задач.
Не начинай следующую задачу автоматически: одна задача выполняется за один рабочий шаг.

# S19. Размещение пилота

Статус: не начата. День 3. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [18-two-hour-reminders.md](18-two-hour-reminders.md).

## Цель

Сделать Mini App, API, базу и уведомления доступными независимо от ноутбука.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Подготовка размещения S16, готовые API/TMA и worker S17–S18.
- Согласованный запуск, доступ к выбранному хостингу и способ безопасного задания секретов.

## Выполнить

1. Подготовить production-конфигурацию, сборку frontend/API/worker, миграции и инструкции отката.
2. Настроить HTTPS API, допустимые frontend-origin и Telegram-адреса; сохранить GitHub Pages как вариант статического frontend.
3. Проверить отсутствие токена бота, dev-входа, HTTP-моков и секретов в сборке frontend.
4. Подготовить резервное копирование БД, проверки работоспособности и контроль остановки worker.
5. После явного согласования конкретного размещения выполнить публикацию и применить миграции; если авторизация уже дана, повторно её не запрашивать.
6. Записать адреса, версии, применённые миграции и результаты проверки в журнал, не включая секреты.

## Критерии готовности

- [ ] Приложение открывается в Telegram; API, БД и задания работают при выключенном локальном процессе.
- [ ] Frontend обращается к HTTPS API; deep links корректны для GitHub Pages.
- [ ] Есть воспроизводимая инструкция запуска/отката и проверено восстановление необходимых данных.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Полный набор проверок изменённых частей и production-сборка до публикации.
- После публикации проверить health/readiness, вход, чтение/создание тестовой игры и работу worker.
- Проверить резервную копию/восстановление в изолированной среде; не испытывать разрушительные сценарии на пилотных данных.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не считать локальный туннель постоянным размещением. Без требуемого внешнего доступа зафиксировать блокировку и не заявлять запуск.

запиши остаток и продолжай эту же задачу следующей сессией. Обнови статус этого файла и индекс задач.

# S09. NestJS и локальная база

Статус: не начата. День 2. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [08-organizer-ui-links.md](08-organizer-ui-links.md).

## Цель

Поднять минимальный backend с PostgreSQL, безопасной конфигурацией и проверками.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Архитектура S01, контракт S03, корневые команды проверок.

## Выполнить

1. Создать workspace `backend/` на NestJS и локальный PostgreSQL с воспроизводимым запуском.
2. Настроить конфигурацию окружения с валидацией, пример без секретов, CORS для известных frontend-origin.
3. Добавить health/readiness, ID запроса и структурированные логи с исключением initData, токенов и персональных данных.
4. Создать команды форматирования, линта, типов, тестов, контрактной проверки и сборки.
5. Описать локальный запуск, подключение БД, обработку завершения процесса и границу публичного API.

## Критерии готовности

- [ ] API запускается локально; readiness отражает доступность БД.
- [ ] Некорректная конфигурация останавливает запуск понятной ошибкой без утечки секретов.
- [ ] Команды backend-проверок определены и проходят на каркасе.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, тесты конфигурации/health, проверка согласования с контрактом и сборка.
- Проверить запуск с доступной/недоступной БД и корректное завершение процесса.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не разворачивать production, не создавать микросервисы и не добавлять Redis без необходимости.

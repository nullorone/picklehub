# S04. TanStack Query и моки HTTP API

Статус: не начата. День 1. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.

## Выполнить

1. Подключить TanStack Query, единый API-клиент, настройку базового URL и согласованные query keys.
2. Организовать моки на HTTP-границе, например через MSW, с моделями из контракта.
3. Подготовить сценарии списка, пустых данных, деталей, ошибок, задержки, заполненной и отменённой игры, организатора без участия и двух пользователей.
4. Определить стратегию обновления списка/деталей/состава после мутаций и восстановление при ошибках.
5. Отделить mock/dev-режим от пилота; не хранить серверное состояние одновременно в Zustand и Query.

## Критерии готовности

- [ ] Один клиент обращается к HTTP-мокам; переход на API требует смены конфигурации, а не переписывания компонентов.
- [ ] Ошибки и задержки воспроизводимы, dev-личность не выдаётся за реальную Telegram-авторизацию.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, контрактные проверки и сборка.
- Проверить ответ моков по схемам и обновление кэша после успешной и неуспешной команды.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не создавать собственный второй набор DTO и не реализовывать backend.

# S01. Основа frontend и npm workspace

Статус: в работе. HTTP, форматирование, линт, типы и сборка пройдены; запуск HTTPS через mkcert заблокирован ответом
HTTP 403 от GitHub API при загрузке бинарного файла mkcert. День 1. Бюджет одной сессии: 30–60 минут, плановая оценка —
60 минут.
Предыдущая задача: завершённое интервью и ADR-001.

## Цель

Получить работающий каркас Telegram Mini App с сохранённым локальным запуском.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- `package.json`, корневой lock-файл, `vite.config.ts`, `src/`, `.github/workflows/`.
- [Визуальная основа](../_docs/legacy-prototype.md).

## Выполнить

1. Описать в `llm/_docs/architecture.md` минимальные границы TMA, API, контракта, токенов и будущего backend; правила зависимостей и генерируемого кода.
2. Создать npm workspaces с единым корневым lock-файлом и перенести основу React/Vite в `frontend/tg/`, сохранив текущий визуальный ориентир.
3. Сохранить корневые команды `start`, `start:https`, `build`, `deploy`; при необходимости поправить пути сборки и GitHub Pages workflow. Публикацию в этой задаче не выполнять.
4. Настроить строгий TypeScript, форматирование, ESLint и команды проверок. Исправить известную проблему typed ESLint без отключения правил ради успешной проверки.
5. Оставить каркас приложения доступным без продуктовых функций; отладочные возможности и mock Telegram environment явно ограничить режимом разработки.

## Критерии готовности

- [x] Установка использует один lock-файл; TMA запускается и собирается из корня.
- [ ] HTTPS через mkcert сохранён и его запуск проверен; не заявлять наличие туннеля, если он отдельно не настроен.
- [x] Записаны команды проверок и границы будущих модулей; контрактный генератор ещё не требуется.
- [x] Доступные проверки выполнены, точные команды и результаты записаны в журнал. Проверка HTTPS остаётся открытой.

## Проверки

- Выполнить форматирование, линт, проверку типов и сборку каркаса.
- Проверить локальный HTTP/HTTPS запуск и маршрутизацию; реальные результаты записать в журнал.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не создавать страницы бизнес-сценариев, backend, web/PWA или mobile. Не переносить готовое приложение из эталонной ветки.

# S06. Форма создания игры

Статус: выполнена 2026-09-25. День 1. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [05-game-list-details.md](05-game-list-details.md).

## Цель

Создать встречу из интерфейса и открыть её страницу.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Контракт S03, HTTP-моки S04, маршруты S05.

## Выполнить

1. Сделать форму: площадка, адрес, дата, начало, длительность, лимит, желаемый уровень, описание.
2. Добавить включённый по умолчанию переключатель «Я участвую» и пояснить его влияние на свободные места.
3. Ввод времени площадки — Europe/Moscow для пилота; отправка — UTC, часовой пояс виден пользователю.
4. Использовать ограничения контракта, показывать ошибки полей и серверные ошибки, сохранять ввод при неудаче.
5. Защитить повторное нажатие; после подтверждённого API успеха обновить список и открыть созданную игру.

## Критерии готовности

- [x] На моках встреча создаётся с участием организатора и без участия.
- [x] Пустые/некорректные значения и прошлое время обрабатываются; ошибочный ответ не выглядит успешным созданием.
- [x] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, тесты формы и преобразования времени, контрактные проверки и сборка.
- Проверить повторный клик, API-ошибку и сохранность введённых данных.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не добавлять справочник площадок, оплату, автоматическую ротацию или повторяющиеся встречи.

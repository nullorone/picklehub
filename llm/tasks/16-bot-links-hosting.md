## Цель

Обеспечить вход через бота и подготовить рабочее окружение пилота.

- Актуальные официальные правила Bot API, Mini App deep links и выбранного хостинга.

## Выполнить

1. Реализовать /start с открытием Mini App, обработать передачу идентификатора игры через Telegram start parameter.
2. При открытии ссылки восстанавливать маршрут игры после авторизации; неверные и неизвестные идентификаторы обрабатывать безопасно.
3. Связать чат бота с проверенным Telegram-пользователем, учитывать отсутствие права отправки и блокировку бота.
4. Выбрать для разработки публичный HTTPS-доступ к API при необходимости; mkcert не считать публичным туннелем.
5. Подготовить конкретный вариант хостинга API, БД и worker с учётом правил размещения данных, стоимости и условий; описать конфигурацию, миграции, резервирование и rollback.
6. Зафиксировать необходимые действия владельца для аккаунта/оплаты/секретов; не требовать отправки токенов в переписку.

## Критерии готовности

- [ ] Пользователь запускает бота и открывает конкретную игру через ссылку.
- [ ] Известно, какие пользователи доступны для личных сообщений.
- [ ] Есть конкретный план размещения, переменные окружения без значений секретов и список оставшихся внешних действий.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, тесты обработки ссылок/update, контрактные проверки и сборка.
- Проверить реальный переход в Telegram, неверный идентификатор и отсутствие доступа к отправке; реальные сообщения только тестовым участникам согласованной проверки.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

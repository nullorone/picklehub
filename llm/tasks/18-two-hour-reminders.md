# S18. Напоминания за два часа

Статус: выполнена. День 3.
Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [17-change-notifications.md](17-change-notifications.md).

## Цель

Напоминать актуальным участникам о предстоящей встрече через устойчивое задание.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Worker S17, данные/события S10/S14 и правила напоминаний плана.

## Выполнить

1. Планировать напоминание на начало минус два часа; задания хранить в БД с ключом встречи/версии времени.
2. При переносе времени отменять старое задание и планировать новое, если срок ещё не прошёл.
3. Перед отправкой проверять текущее время/версию, отмену и актуальный состав; вышедшие и удалённые участники исключаются.
4. Организатор получает напоминание только если занимает место; поздняя запись после порога не создаёт просроченное напоминание.
5. Определить и задокументировать допустимое окно опоздания worker; после начала встречи напоминание не отправляется.
6. Использовать управляемые часы в тестах, чтобы не ждать два часа реально.

## Критерии готовности

- [x] Напоминание приходит текущим участникам за два часа, с актуальными временем и ссылкой.
- [x] Перенос, отмена, выход и перезапуск не приводят к отправке устаревшего задания.
- [x] Повтор обработки не создаёт новый набор заданий.
- [x] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, контрактные проверки и сборка.
- Тесты с управляемым временем: порог, поздняя запись, перенос вперёд/назад, отмена, выход, перезапуск и начало встречи.
- Подтвердить ограниченную реальную доставку тестовому аккаунту с явно описанным способом проверки времени.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не добавлять пользовательские настройки расписания и несколько напоминаний.

результаты, фактическое время, блокировки и оставшаяся работа. Если час закончился до приёмки,
запиши остаток и продолжай эту же задачу следующей сессией. Обнови статус этого файла и индекс задач.
Не начинай следующую задачу автоматически: одна задача выполняется за один рабочий шаг.

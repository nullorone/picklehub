# S15. Подключение TMA к настоящему API

Статус: не начата. День 2. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [14-organizer-api.md](14-organizer-api.md).

## Цель

Пройти пользовательские сценарии с постоянным хранением данных.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Frontend S05–S08, авторизация и API S11–S14.

## Выполнить

1. Настроить подключение frontend к локальному backend через тот же сгенерированный клиент.
2. Подключить Telegram-сессию, обработку истечения авторизации и повторный вход.
3. Проверить создание, список, детали, запись, выход и управление; устранить расхождения контракта через TypeSpec.
4. Обновлять Query-кэш после мутаций и при возвращении на экран; обработать изменения другим пользователем без WebSocket.
5. Явно выключить HTTP-моки в интеграционном и пилотном режиме, оставить отдельный режим разработки.

## Критерии готовности

- [ ] Два аккаунта видят общую встречу и изменения состава.
- [ ] Перезагрузка страницы и backend не теряет данные; отсутствие сети не выдаёт ложный успех.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, относящиеся интеграционные/UI-тесты, контрактные проверки и сборка.
- Пройти сквозной сценарий с двумя реальными аккаунтами; если это недоступно, записать блокировку, не выдавать моки за проверку.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не добавлять realtime-сокеты или переписывать модели вручную для обхода несоответствий API.

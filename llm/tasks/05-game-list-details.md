# S05. Список и страница игры

Статус: не начата. День 1. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [04-query-api-mocks.md](04-query-api-mocks.md).

## Цель

Показать будущие встречи и достаточно информации для решения о записи.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Токены S02, контракт S03, Query и моки S04.

## Выполнить

1. Сделать список будущих игр и маршрут конкретной игры по идентификатору.
2. Показывать дату, время с часовым поясом, площадку, желаемый уровень, заполненность и статус.
3. На странице игры показать адрес, длительность, описание, организатора и текущих участников.
4. Разделить роль организатора и его участие: организатор без места не должен увеличивать счётчик.
5. Добавить загрузку, пустой список, ошибку с повтором, отсутствие сети, неизвестную и отменённую игру.

## Критерии готовности

- [ ] Переход из списка и прямое открытие URL приводят к одной игре.
- [ ] Число мест и статус согласованы с контрактом; UTC корректно отображается в часовом поясе пользователя.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, относящиеся UI-тесты, контрактные проверки и сборка.
- Проверить состояния моков, мобильную ширину, длинный адрес и обе темы.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не добавлять карту, поиск по геолокации, сложные фильтры или профиль игрока.

## Завершение сессии

Обнови [журнал](../_docs/ai-development-log.md): изменения, принятые решения, команды,
результаты, фактическое время, блокировки и оставшаяся работа. Если час закончился до приёмки,
запиши остаток и продолжай эту же задачу следующей сессией. Обнови статус этого файла и индекс задач.
Не начинай следующую задачу автоматически: одна задача выполняется за один рабочий шаг.

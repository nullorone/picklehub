# S14. API управления встречей

Статус: не начата. День 2. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [13-join-leave-transactions.md](13-join-leave-transactions.md).

## Цель

Безопасно редактировать встречу, удалять участников и отменять её.

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Контракт S03, схема заданий S10, транзакции S13.

## Выполнить

1. Реализовать серверную проверку владельца для редактирования, удаления и отмены.
2. Проверять лимит относительно актуального состава в той же транзакционной стратегии, что запись.
3. Поддержать переключение участия организатора; включение требует свободного места, выключение сохраняет владение.
4. Отмену хранить как состояние, сохранять состав для уведомлений; повторная отмена не создаёт новые события.
5. Атомарно записывать задания изменений/отмены/удаления и обновлять будущие напоминания по правилам плана.

## Критерии готовности

- [ ] Обычный участник не управляет чужой встречей даже прямым API-запросом.
- [ ] Удаление освобождает место; отмена закрывает запись; лимит не опускается ниже состава.
- [ ] Сбой записи задания откатывает изменение; повторы не размножают события.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, контрактные проверки и сборка.
- Интеграционные тесты прав, повторной отмены, конкурентной записи с изменением лимита/отменой, атомарности заданий.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не вводить платформенную модерацию, баны, административную панель или автоматическое исключение при уменьшении лимита.

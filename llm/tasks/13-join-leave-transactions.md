# S13. Транзакционная запись и выход

Статус: не начата. День 2. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [12-game-api.md](12-game-api.md).

## Цель

Защитить последнее место и исключить дубли участия.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- Контракт S03, схема/транзакционная стратегия S10, API S12.

## Выполнить

1. Реализовать запись в транзакции с проверкой статуса, времени и вместимости под выбранной защитой конкуренции.
2. Использовать уникальность участия и контракт повторного запроса, обрабатывать ожидаемые конфликты БД.
3. Реализовать собственный выход до начала; освобождение места не должно менять права организатора.
4. Все операции изменения состава должны использовать совместимый порядок блокировок с будущим удалением и изменением лимита.
5. Возвращать актуальный результат и ошибки по контракту, без ложного успеха при заполнении.

## Критерии готовности

- [ ] При двух конкурентных запросах на последнее место проходит один; лимит не превышается.
- [ ] Повторная запись не дублирует участника; повторный выход имеет согласованный результат.
- [ ] Отменённая/начавшаяся встреча не принимает запись.
- [ ] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, контрактные проверки и сборка.
- Интеграционные тесты на настоящем PostgreSQL: последнее место, повтор одного пользователя, выход/запись и закрытые состояния.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не заменять конкурентный тест последовательным; не добавлять FIFO-очередь.

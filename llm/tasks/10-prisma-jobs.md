# S10. Prisma-модели, миграции и устойчивые задания

Статус: выполнена 2026-09-25. День 2. Бюджет одной сессии: 30–60 минут, плановая оценка — 60 минут.
Предыдущая задача: [09-backend-foundation.md](09-backend-foundation.md).

## Цель

Подготовить хранение встреч, участия и уведомлений с транзакционными инвариантами.

## Перед началом

Прочитай корневой `AGENTS.md`, [обзор проекта](../00-project-overview.md),
[порядок работы](../README.md), [требования MVP](../_docs/telegram-mvp-plan.md),
[ADR-001](../_docs/adr-001-telegram-first-mvp.md) и
[результаты предыдущих задач](../_docs/ai-development-log.md).
Если приёмка предыдущего шага не завершена, сначала закончи его.

- NestJS/БД S09, контракт S03 и рабочие допущения плана.

## Выполнить

1. Определить пользователя с Telegram identity, сессию, встречу, организатора, участников и состояние отмены.
2. Создать миграции с уникальностью пары встреча/пользователь, внешними ключами и ограничениями значений.
3. Выбрать и описать механизм сериализации записи в состав: блокировка встречи либо эквивалентная транзакционная защита.
4. Выбрать минимальную устойчивую очередь заданий; PostgreSQL-таблица с атомарным захватом допустима. Зафиксировать решение и правила повторов.
5. Изменение встречи и запись задания должны совершаться в одной транзакции; предусмотреть версию события, ключ дедупликации, попытки и восстановление зависших заданий.
6. Подготовить только синтетические локальные данные. Чувствительные данные не включать в fixtures.

## Критерии готовности

- [x] Миграции применяются к чистой БД; схема поддерживает организатора без участия.
- [x] Уникальность участия обеспечивается БД; описана защита лимита при конкуренции.
- [x] Задания хранятся устойчиво, не только в памяти процесса.
- [x] Проверки выполнены, точные команды и результаты записаны в журнал.

## Проверки

- Форматирование, линт, типы, генерация Prisma, контрактные проверки и сборка.
- Интеграционно проверить ограничения БД, миграции и откат совместной записи встречи/задания.
- Выполнить `git diff --check`; проверить ссылки и форматирование изменённых документов.
- Не ослаблять проверки и не выдавать непроведённые проверки за успешные.

## Границы задачи

Не считать предварительную проверку числа участников достаточной защитой; не реализовывать доставку до S17.

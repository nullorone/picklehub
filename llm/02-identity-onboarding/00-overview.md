# Идентификация и первичная настройка: контекст

Один профиль связывает учётные данные Telegram и электронной почты через magic-ссылку. Активация — завершённая
первичная настройка. Обязательны отображаемое имя, часовой пояс, предпочтительная география, предпочтения одиночной
и парной игры, самооценка уровня и согласия; DUPR — необязательная внешняя ссылка.

Данные инициализации Telegram проверяются на backend. Magic-ссылки одноразовые и хешируются. Web и TMA держат
access-токен в памяти, а ротируемый refresh-токен — в cookie HttpOnly. Связывание учётных данных требует повторного
подтверждения обеих сторон.

Возраст и документы не проверяются. Премиум-возможности, социальный OAuth и аутентификация по паролю не входят в
объём работ.

Для локальной разработки web поддерживает явный `LOCAL_AUTH_BYPASS=true` только при `NODE_ENV=local`.
Он автоматически создаёт обычную сессию выделенного тестового игрока без письма. Первичная настройка,
согласия, ограничения аккаунта и проверки Origin/CSRF сохраняются. Telegram, mobile и административный
вход не используют этот режим. По умолчанию режим выключен.
При старте локального API с включённым режимом создаются недостающие тестовые документы TERMS и PERSONAL_DATA.
Они явно обозначены как материалы для разработки; существующие версии не заменяются, согласия не принимаются
автоматически. В остальных окружениях эта инициализация выключена.

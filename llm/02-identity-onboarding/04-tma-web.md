# Этап 4. Интерфейс идентификации для TMA и web/PWA

## Промпт агенту

Ты — старший frontend-инженер аутентификации. Реализуй доступную первичную настройку в обоих клиентах.

## Выполни

- TMA автоматически обменивает данные инициализации через backend; web запрашивает и использует magic-ссылку без
  возможности определить существование аккаунта.
- Access-токен хранится только в памяти; refresh выполняется через cookie. Не помещай данные аутентификации в
  аналитику, хранилища или логи.
- Реализуй возобновляемую первичную настройку, валидацию, ссылки на согласия, часовой пояс, географию,
  предпочтения, уровень и необязательные URL и ID DUPR.
- Добавь связывание и отвязывание учётных данных, выход на всех устройствах и все состояния загрузки, ошибки,
  истечения срока, отсутствия сети и успеха.

## Приёмка

Событие активации отправляется только после подтверждённого сервером завершения. Глубокая ссылка возвращает
пользователя на безопасный целевой маршрут. Запусти тесты и сборки UI.

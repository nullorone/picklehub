# Интерактивные сообщения Telegram для PickleHub

Дата исследования: 5 ноября 2026 года.
Статус: выводы для будущей реализации; интеграция не начата.

## Вывод и доступность

Виджеты подходят для карточки игры PickleHub с записью и отменой участия прямо в чате.
Создание событий и сложные формы целесообразно оставить в Telegram Mini App.

На момент исследования документация официального репозитория `TelegramMessenger/widget-sandbox`
описывает Bot API 10.4 и проверки через beta API. Публичная справка Bot API при этом показывает
версию 10.3 без метода `sendWidget`. Массовая доступность виджетов для обычных ботов и всех
клиентов Telegram не подтверждена. Перед реализацией необходимо заново проверить документацию,
доступность методов и поддержку на конкретных версиях клиентов.

Документация репозитория местами расходится: корневой README содержит более старые сведения
об отсутствии запросов к боту, тогда как SDK и руководство автора описывают `TelegramWidget.request`.
Названия методов ниже относятся к описанной beta 10.4 и требуют повторной проверки перед разработкой.

## Принцип работы

Бот отправляет самостоятельный HTML-документ со встроенными CSS и JavaScript.
Telegram отображает его внутри сообщения. JavaScript выполняется в изолированной среде QuickJS,
а доверенная часть клиента проверяет разрешённые элементы, стили и операции перед отрисовкой.
Сам виджет не имеет прямого доступа к сети.

Последовательность взаимодействия:

1. Бот отправляет карточку и её начальное состояние.
2. Пользователь нажимает кнопку, например «Участвую».
3. Виджет вызывает `TelegramWidget.request(...)` с короткой командой.
4. Telegram доставляет запрос боту с идентификатором пользователя.
5. Сервер PickleHub проверяет действие и сохраняет результат в базе данных.
6. Бот отвечает на запрос и отдельно обновляет состояние виджета.
7. Виджет получает изменение состояния и перерисовывает карточку.

HTML после отправки не меняется: новый шаблон требует нового виджета.
Меняются только данные. Ответ на запрос сам по себе не обновляет общее состояние.

`widget-sandbox` — среда выполнения для клиентов Telegram и инструмент локальной проверки.
Устанавливать этот движок в сервер бота не требуется.

## Состояние и пересылки

- `chatData` — состояние конкретного сообщения в чате. В группе его видят все участники;
  оно не переносится при пересылке и не является персональным состоянием каждого читателя.
- `publicData` — данные для отображения в том числе в пересланных сообщениях.
- У обычного виджета пересылка получает снимок публичного состояния.
- У общего виджета (`is_shared`) сообщения ссылаются на один объект по `widget_id`;
  его публичное состояние может обновляться во всех копиях.

Виджет не должен содержать секреты. В публичное состояние следует передавать только данные,
которые допустимо показать при пересылке. Данные виджета служат представлением;
источником истины для участников и свободных мест остаётся база PickleHub.

## Что показывает пример

В `corpus/bot-demos` есть RSVP-сценарий `03-rsvp.html` и обработчик в `scripts/bot-demos.ts`.
Он поддерживает ответы «иду / возможно / не иду», список участников и ограничение мест.
Бот определяет участника по Telegram ID, обрабатывает `rsvp:in`, `rsvp:may`, `rsvp:out`
и обновляет данные сообщения. Это близкий пример для будущей карточки игры PickleHub.

Демонстрационный бот хранит состояние в JSON-файле и использует long polling.
Для продукта потребуется связать этот сценарий с серверной логикой и базой данных PickleHub,
а не переносить демонстрационное хранение как готовое решение.

## Ограничения

- HTML: не более 32 768 байт исходного текста и 4096 байт после сжатия zlib сервером.
- CSS, JavaScript и изображения должны быть встроены; внешние ресурсы и сетевые запросы недоступны.
- Нет текстового ввода, клавиатуры и внутренней прокрутки; высота ограничена 600 px.
- Поддерживается ограниченный набор HTML, CSS и DOM API, а не полноценная браузерная среда.
- React-интерфейс Mini App нельзя просто перенести целиком: нужен компактный самостоятельный шаблон.
  Внешний вид следует согласовать с дизайн-системой PickleHub с учётом разрешённого профиля.
- Команда запроса занимает 1–64 байта; `chat_data`, `public_data` и ответ — до 1024 байт каждый.
- Поддержка отображения зависит от версии и настроек клиента Telegram.

## Что потребуется для реализации

1. Проверить beta или стабильный API на отдельном тестовом боте и поддерживаемых клиентах.
2. Подготовить HTML-карточку игры: дата, площадка, число мест, кнопки участия и ссылка в Mini App.
3. Добавить адаптер отправки и обновления виджетов в бота.
4. Подключить обработчики к серверной логике участия: права пользователя, доступные места,
   повторные запросы и одновременная запись на последнее место.
   Инварианты защищать транзакциями, ограничениями базы и идемпотентностью.
5. Хранить связь события с сообщениями и, если понадобится общий виджет, с `widget_id`.
6. Обрабатывать ожидание, ошибки и повторные попытки; отвечать на каждый запрос виджета.
7. Предусмотреть обычное сообщение с кнопками и переходом в Mini App для клиентов без поддержки.
8. Проверить карточку в sandbox, на телефонах и настольных клиентах, в личном чате и группе.

Методы и обновления, описанные для beta 10.4:

| Задача | API |
| --- | --- |
| Отправить виджет | `sendWidget` |
| Отправить существующий общий виджет | `sendSharedWidget` |
| Получить действие | `widget_query`, `shared_widget_query` |
| Ответить на действие | `answerWidgetQuery` |
| Обновить данные сообщения | `editMessageWidgetData` |
| Обновить общее состояние | `editSharedWidgetData` |

## Первый прототип при возвращении к задаче

Сценарий: «карточка игры → записаться → обновить число участников → отменить участие».
Проверить его в личном чате и группе, включая повторное нажатие и конкуренцию за последнее место.
Затем отдельно оценить общие виджеты и поведение пересылок.

Прототип должен подтвердить доступность API, поддержку клиентов и пригодность сценария.
Платежи и бронирование кортов в эту работу не входят.

# PickleHub Telegram Mini App

Monorepo для Telegram MVP PickleHub. Текущее приложение находится в `frontend/tg/`; архитектурные границы и порядок
дальнейшей работы описаны в `llm/_docs/architecture.md` и `llm/README.md`.

## Установка и запуск

В корне репозитория используется один `package-lock.json`:

```sh
npm ci
npm run start
npm run start:https
```

`start:https` создаёт локальный HTTPS-сертификат через mkcert. Он не создаёт публичный туннель.
По умолчанию локальный frontend работает на моках. Прежний backend, контракты и настройки их запуска удалены
для самостоятельного обучения. Каталоги `backend/` и `contracts/` оставлены пустыми.

## Проверки и сборка

```sh
npm run format
npm run lint
npm run typecheck
npm run build
```

Результат сборки Mini App находится в `frontend/tg/dist/`. `npm run deploy` публикует статический frontend в GitHub Pages;
публикация backend в этот процесс не входит.

## Самостоятельная разработка backend

Порядок обучения: вход через Telegram и права доступа → создание, получение, изменение и удаление события →
список событий → профиль. Новый код и контракт пишет разработчик; наставник объясняет материал, даёт небольшие
примеры и проверяет результат.

Пакет `frontend/packages/api` временно сохраняет прежний сгенерированный клиент для существующего frontend.
После создания нового контракта клиент нужно будет сгенерировать заново. Материалы в `llm/` описывают прежние
решения и планы; инструкции запуска старого backend больше не применимы.
